**Nodes**: VPN servers wherever you need them, added to the web UI by themselves.

A node is a trapdoor agent with its VPN container. It runs OpenVPN, WireGuard and AmneziaWG
servers, on the machine with the web UI or anywhere else, and a machine can have several
nodes (e.g. one per network). The web UI now shows everything as **machine › node › VPN
server**.

## Nodes join by themselves

- **Nodes → Add a node → With a join token**: a one-time token (valid 1 hour to 7 days,
  optionally for one node name) and the five `.env` lines for the node, ready to copy. The
  node connects to the web UI when it starts; the web UI connects back with the node's
  certificate pinned, as before. No more copying fingerprints by hand.
- Nodes in the web UI's own compose file join with a shared `TD_JOIN_SECRET`.
- Restarts of a known node (same certificate) need no token; a used or expired token, or a
  different certificate for an existing node, is refused.
- Adding a node by hand (address, token, fingerprint) still works.

## Clearer where everything runs

- **Nodes page**: every machine with its nodes, each node's containers and its VPN servers
  with their state, and *Add a server on this node*.
- **Servers page** grouped by machine › node.
- **Add a server** asks for the node first; the summary says exactly where the server goes
  (node, machine, container, port).
- Every page shows where the selected server runs, e.g. *my-mac › node office · container
  vpn-office*.
- `TD_MACHINE` and `TD_NODE_NAME` name a node's machine and itself.

## Examples

- [**Nodes**](https://github.com/shuricksumy/trapdoor/tree/main/examples/nodes): the web UI
  and three nodes in one compose file, each with its own folder, network stack, NAT,
  firewall and ports (replaces *separate containers*), with a variant for one node on the
  host's network.
- [**Remote machines**](https://github.com/shuricksumy/trapdoor/tree/main/examples/remote):
  set up with a join token.

## Upgrading from 0.1

Nothing to change: hosts added in 0.1 are nodes now, with the same ids (`<node>.<id>`) and
history. `/api/v1/hosts` keeps working next to the new `/api/v1/nodes`. Update the web UI
and the other machines' agents around the same time.
