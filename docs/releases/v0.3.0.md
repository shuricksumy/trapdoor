**Backups on a schedule, email, and client lifetimes.**

## Scheduled backups

- Account → *Scheduled backups*: every day or every week at a set hour, into `/data/backups`
  of the web container (or a host / NAS folder you mount there)
- Each run saves everything (every node included) and, if you like, one file per server, so
  a single server can be restored or moved
- The newest N files of each kind are kept, older ones deleted
- Encrypted with `TD_BACKUP_PASSPHRASE` (kept out of the database: the folder alone cannot be
  opened); the page warns when it is not set
- Last run, next run, *Back up now*, download and delete; the Servers page shows a line, or
  the error when the last backup failed
- A run missed while the web UI was down runs when it is back

## Email

- Account → *Email*: an SMTP server (STARTTLS, TLS, or a local relay), the sender and the
  admins' addresses; *Save and send a test*
- **Send clients their access**: OpenVPN *More → Email the profile*, WireGuard / AmneziaWG
  *More → Email the config* (with its QR code as an image). The email says which app to
  install and how to connect, with your note. The address is kept for the client
- **Notifications** (each can be turned off): a scheduled backup failed; a node has not
  answered for 5 minutes, and when it is back; certificates and client end dates coming up
- `TD_PUBLIC_URL` adds a link to the web UI under notifications

## Client lifetimes

- OpenVPN: certificates from 30 days to 10 years, or *Until a date…*; a default lifetime per
  server for new clients and renewals (no more renewing family devices every 825 days)
- WireGuard / AmneziaWG: *Works until* per client (also when adding several, e.g. guests).
  After that day the agent takes the client off the server, also while the web UI is down;
  a later date or none brings it back

## Smaller things

- The OpenVPN and WireGuard client tables look alike: the main action, the on/off button
  (Revoke / Restore, Disable / Enable) and a *More* menu
- Picking another server opens its Traffic page; the server list names the node
  (*OpenVPN · office*) and the setup page says which server it sets up
- Both clients pages are at `/clients` (`/certificates` still works)

## Upgrading from 0.2

Nothing to change. Set `TD_BACKUP_PASSPHRASE` in `.env` before turning on scheduled backups,
and update the other nodes' agents together with the web UI (WireGuard end dates need the
new agent).
