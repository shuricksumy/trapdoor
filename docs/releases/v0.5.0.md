**See who reaches what.** A Network page with a map for every server type, routing in one
place, an Access diagram you can click, and display names everywhere.

## Network page

One page per server (menu → Network), the same for OpenVPN, WireGuard and AmneziaWG:

- **Map**: clients on the left (routers first, connected ones with a green line), the
  server in the middle, the networks on the right: each one *through the server* or *behind*
  a client, with who reaches it, and the internet (which clients send everything through
  the VPN). Click a client or a network to change it.
- **Needs attention**, each with a button: a LAN behind a client without a server `route`
  (*Add the route*), a LAN nobody reaches (*Give it to clients*), LANs behind two clients
  that overlap, a server route no client serves. Saved `server.conf` changes offer *Apply and
  restart*, with rollback if OpenVPN does not come back.
- **Clients** tab: connected dot, routers marked, the live address next to "automatic" with
  *Make fixed*, each client's own access rules, *Reconnect* (OpenVPN), search, cards on
  phones.
- **Routing** tab: all traffic through the VPN, client-to-client, the routes every client
  gets and the networks the server sends into the VPN, each with where it is. WireGuard /
  AmneziaWG: the default allowed IPs, with a switch for all traffic.
- **Named networks** tab (OpenVPN).
- WireGuard / AmneziaWG: the map comes from the allowed IPs; a client's address, allowed IPs,
  DNS and LANs are edited right on the page.

With `client-to-client` (common on servers set up by openvpn-ui) OpenVPN carries client
traffic to LANs behind other clients itself, so a missing server route is not flagged there.

## Access diagram

The Access page shows what the rules mean for a client: this server, other VPN clients, the
networks the server routes and the internet, each allowed or blocked. Click one to switch it
for every client; it becomes an ordinary rule, after the rules for single clients so those
still win. A *Good to know* box says what the rules need (routes, fixed addresses,
client-to-client off, `TD_FIREWALL`).

## Display names

An OpenVPN client's display name ("Anna's phone") shows on every page now: Overview,
Connected, Traffic, Network and Access, with the login in the tooltip.

## Also

- The sidebar shows the version and links to GitHub; the name is "Trapdoor".
- WireGuard / AmneziaWG get the same Overview and Server pages as OpenVPN.
- Naming routes that clients already have no longer rewrites their ccd files.

## Moved

- OpenVPN: full tunnel, client-to-client and the routes moved from the Server page to
  Network → Routing (the raw `server.conf` editor still has everything).
- WireGuard / AmneziaWG: the default allowed IPs moved from the server settings to
  Network → Routing.

## Tests

The map, the routing editors and the Access switches have unit tests; the e2e test checks
with real OpenVPN and WireGuard that a server route becomes a kernel route into the tunnel,
the routing switches render into `server.conf`, the default allowed IPs reach client
configs, a client's LAN reaches the interface at once, and the Access switches' rule shapes
filter real traffic.

## Upgrading from 0.4

`docker compose pull && docker compose up -d`. Nothing to change.
