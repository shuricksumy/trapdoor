**Know when, and find out why.** An Uptime page for any period, Telegram and online / offline
messages, and network tools that run from the VPN server itself.

## Uptime

Menu → *Uptime*, for every server type:

- **Any period** back to the first record (the session history is never deleted): Today,
  7 days, 30 days, This month, Last month, This year, or any dates; one client or all; *Hide
  quick reconnects*. The filters are in the address, so a view can be bookmarked.
- **Summary**: online now, average uptime, time online, sessions, ups and downs.
- **Status bars** by hour (up to 3 days) or by day: each hour or day split by time, so even a
  one-minute connection or a short drop shows. **Green**: online; **red**: not connected while
  the server was up; **empty**: the server was down. A **Server** row with its own uptime: every
  answer to the history poll is now recorded, so an outage of the server is told apart from a
  client being offline.
- **Calendar** per client: hours online per day, a day's ups and downs.
- **Ups and downs**: every connect and disconnect, in pages of 25 / 50 / 100, with where from
  and how long, and a CSV export.

## Telegram and online / offline messages

- **Telegram** next to email (Account → *Telegram*): your own bot's token and chat ids, a test
  message, and the same admin notifications (backup failed, node down, certificates expiring),
  each on or off.
- **Client online / offline**: one email address and / or one Telegram chat (Account → *Client
  online / offline*), turned on per client (Clients → *More* → *Online / offline messages*; a 🔔
  marks them). A reconnect within the quiet time (2 minutes by default) stays quiet. Messages use
  display names: *🟢 Anna's phone (anna) is online on OpenVPN since Nov 20 14:02 from 203.0.113.45.*

## Tools

Menu → *Tools*: ping, traceroute, DNS (also asking a chosen DNS server), TCP ports, HTTP(S)
(status, timing, certificate) and routes, run from the VPN server's own network, so they reach
what the server reaches: clients' VPN addresses, the LANs behind them, the internet. Suggestions
for the server, connected clients and their LANs. No shell; targets must be an IP or a host
name; one run at a time per node; every run in the audit log.

## Also

- The menu ends with *Tools* and *Server*.
- Relative times within a day say "13 hours ago", not "yesterday".

## Upgrading from 0.5

`docker compose pull && docker compose up -d`. The web database gets two new tables on start
(online / offline choices and the servers' up time). For the Tools, the agent needs NET_RAW for
traceroute, which Docker gives by default and the compose files keep.
