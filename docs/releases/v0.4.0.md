**Scripts and extra rules per server**, and a fix for the Traffic page.

## Scripts and extra rules

Every server (OpenVPN, WireGuard, AmneziaWG) has *Scripts and extra rules* on its page. They
run in the server's vpn container, as root, while the server is up, and are undone when it
stops.

- **Presets**: send the clients' DNS to your AdGuard / Pi-hole, block DNS-over-TLS and
  DNS-over-QUIC (port 853) so apps fall back to it, keep clients from reaching each other
- **Own scripts**: *On start* / *On stop* (`sh`), with `$IFACE`, `$SUBNET`, `$SERVER_ID`,
  `$TYPE`, `$NAT_IFACE`. Because they run as root, the web UI may edit them only on nodes
  whose agent has `TD_SCRIPTS=on`; otherwise they are files in the server's folder, shown
  read-only and picked up within a second
- A change applies without restarting the server; the page shows *Running*, *Failed* (with
  the error) or *Server not running*
- Replaces `PostUp` / `PostDown` from WGDashboard-style setups and OpenVPN's `up` / `down`

## Fixed

- A connection that had not logged in yet, or whose login failed, showed up as a client
  "UNDEF" on the Traffic and Connected pages. It is ignored now, and the rows stored before
  are removed when 0.4 starts.

## Upgrading from 0.3

`docker compose pull && docker compose up -d`. To edit own scripts in the web UI, add
`TD_SCRIPTS: "on"` to the agent of each node where you want it. Update the other nodes'
agents together with the web UI (the scripts are run by each node's vpn container).
